# v0.8 一覧同期と制作体験

## MEGA一覧の不具合

MEGAJS 1.3.10の実コードと、Node版・ブラウザ版双方のローカルAPI応答テストで確認した事項：

1. `reload()` は既存IDのノードを再利用し、最新応答の親へ付け直さない。`keepalive:false` の本アプリでは、移動を追う通知がないためゴミ箱への移動後も古い親に残る。
2. `_importFile()` は親が既に存在するときだけ子を接続する。子が先に届くと、その子が一覧につながらず、次回reloadでも既存IDなので修復されない。
3. reloadごとに通知リスナーが追加される。

`mega-tree.js` は、同じ認証済みStorageとAPI接続で空のノードマップへ読み込み、全件を取得した後で親子関係を作り直す。完了したスナップショットに含まれないIDは残さない。root/trash未取得や通信失敗時は旧マップを復元する。新規に追加された通知リスナーは除き、既存のものを保持する。この再取得処理ではユーザーの作品ファイルの書き換え・移動は行わない。ユーザーがゴミ箱移動を選んだ場合は、要求の成功と一覧からの消失を確認し、未反映なら警告を表示する。

固定バージョンのSDK内部インターフェイスに依存するため、ライブラリ更新時は実SDKの回帰テストが必須。vendor自体は変更しておらず、ビルド時のnpm一致確認を維持している。認証情報の永続化・ログ出力は追加していない。

実アカウントの作品復旧はユーザーによる確認が必要。コード上の不具合の再現・修正確認と、実アカウントでの復旧は区別する。

## 制作画面

- 衣装選びを表示モード・管理操作より前へ。
- 衣装設定は系統、素材、手書き補足、露出・着用状態、参考ブランドの順。
- 大分類の衣装→情緒→状況を維持。詳細の場所・時を構図・撮影より先へ。
- 仕上がり・文章量・コピーをプレビューに集め、狭い幅では固定の「仕上がりを見る」「プロンプトをコピー」で到達。
- 元案の選択肢・カタログ・保存形式は保持。管理ボタンを制作内容より控えめに表示。

390pxの初期画面で衣装選択ボタン上端は約427px（v0.7.1では約653px）。同じブラウザでの参考値であり、フォント・画面環境により変わる。

## 手の描写

無条件の「自然にリラックスした指」は、スマホ等を握る場面と食い違うため削除。全文章量・両仕上がりに共通の短い「手と接触」を追加し、持ち主、身体の連続性、自然な本数・関節、接触、動作の両立、鏡像の整合を指定する。見えない指の全表示や固定ポーズは要求しない。

元案のオプション出力は維持。既存645ケースは今回の明示的な差分のみを戻したとき元のSHAに一致することを確認する。保存済み作品の本文は変更しない。設定を復元して新しく組み立てるプロンプトには改訂が反映される。

画像生成による改善率の比較実験は行っていない。効果は生成モデルや場面に左右され、手の破綻を必ず防げるものではない。
