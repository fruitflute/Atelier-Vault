# v0.8.1 同期診断

## 確認できたことと未確定なこと

ユーザーはv0.8を使用し、MEGA公式側ではアップロード済み作品が存在するが、アプリのカードが欠けると報告。保存直後は反映未確認と表示されるが、次の手動更新では警告が消えていた。

この更新は実アカウントの原因修正・復旧を確認したものではない。保存処理の成功を一覧表示の成功と混同せず、未知の失敗箇所を特定するための診断を追加する。

## 変更

- 保存完了時の作品フォルダID・親ID・record.jsonのIDを接続中のメモリだけに保持。表示できるまで各更新で照合する。ページ再読み込みや切断で消える。既存作品の診断には全体件数を使う。画像の再アップロードは要求しない。
- 一覧に作品フォルダなし／親が異なる／探索対象外／作品情報ファイルなし／名前認識不可／作品情報の読み取り・解析、を区別する。
- 取得ノード数、名前未取得、親未接続、クラウド内のrecord.json数、探索対象外のrecord.json数を表示。ゴミ箱内のrecord.jsonはクラウド件数に含めない。
- 診断情報のコピーは許可したコード・件数・固定の状態文だけ。作品名、プロンプト、ID、パス、URL、認証情報、エラー原文を含めない。自動送信しない。
- 頻度・接続数制限では30秒、クォータ系では60秒のアプリ側休止。サーバーの制限解除時間を示すものではない。期間内の更新は新しい通信を始めず、制限中の追加メタデータ読み取りを保留する。既に進行中の最大4件は完了を待つ。
- 制限・期限切れセッション・SDKが再試行を尽くしたEAGAINはアプリで短時間再試行しない。SDK内部の挙動は変更しない。

## 根拠

[MEGA公式SDKのエラー定義](https://github.com/meganz/sdk/blob/master/include/mega/types.h)と、固定MEGAJS1.3.10の実装に照らしてエラーを分類する。エラーが観測されていなければAPI制限とは断定しない。

公式SDKのfetch-nodes実装も確認したが、リクエスト引数の違いだけを根拠に原因を断定・変更していない。今回のアプリの一覧取得方式はv0.8から変更していない。

## ユーザーによる確認

v0.8.1を開いてMEGAへ接続→ギャラリーを更新→同期状況の「診断情報をコピー」。得られた情報を共有することで次の切り分けを行う。診断表示は再保存・再アップロードを必要としない。
